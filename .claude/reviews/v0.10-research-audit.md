**Synthesis basis:** 3 research streams + 4 audits, cross-checked against the repo. Verified in-repo before writing: agent model pins (`grep '^model:\|^effort:' agents/*.md` → 10× opus / 9× xhigh, 4× sonnet, 0× haiku), the per-Stop haiku agent hook (`hooks/hooks.json:57-61`), the deny-reason duplication (`scripts/gate-write.sh:15` — reason in both `permissionDecisionReason` AND `additionalContext`), the full-SKILL.md SessionStart injection (`scripts/bootstrap.sh:56`, matcher `startup|resume|clear|compact` at `hooks/hooks.json:5`), the random per-invocation nonce (`scripts/inject-learnings.sh:29`), and the undocumented hook events `UserPromptExpansion` / `PostToolUseFailure` (`hooks/hooks.json:18,49`). File sizes confirmed: `claudehut-workflow/SKILL.md` 10,191 B, `implement/SKILL.md` 16,213 B, `review/SKILL.md` 11,125 B, `review-rigor.md` 2,911 B, agents/ 104K on disk.

## 1. Cost diagnosis (why tasks run long & burn tokens)

Ordered by share of burn. Cost-model baseline: trivial task ≈ 25–40K tokens (~3K task-relevant), small ≈ 55–85K, full tier ≈ 190–280K input + 15–25K output ≈ **$2.5–4/task, a 30–60× multiplier over a bare edit+test** — the direct cause of team premium rate-limit exhaustion.

### RC1 — Everything defaults to the expensive path (≈30–40% of burn)
- **Model pins:** 10 of 14 agents pin `model: opus`, 9 at `effort: xhigh` (verified in `agents/*.md` frontmatter). Zero use haiku — even `claudehut-test-runner` (run command, count pass/fail) is sonnet, and checklist reviewers (`claudehut-db-reviewer.md`, `claudehut-contract-reviewer.md`, `claudehut-observability-reviewer.md`) are opus/xhigh with `ultrathink` stacked on top. Opus is $5/$25 vs Sonnet $3/$15 ($2/$10 promo) vs Haiku $1/$5; xhigh thinking bills as output at $25/MTok.
- **Tier routing:** `bin/claudehut-state` (line 57) defaults `complexity: "full"`. If Phase-0 triage is forgotten, a 2-line change runs all 7 phases and 10–16 subagent dispatches — a 6–8× multiplier per missed triage.
- **Frequency:** every subagent dispatch of every task; ~70–80% of full-tier dollar cost is opus-priced.

### RC2 — Review fan-out with uncapped loops (≈25–35% of a full task; the floor cost of a trivial one)
- `skills/review/SKILL.md` (spawn table L61-70) dispatches 4–7 auditors; perf is "Default ON", db/contract fire on any repository/listener/endpoint touch, and only security/observability carry trivial/small skips — so a one-file repository fix still dispatches 3 opus/xhigh agents.
- Each dispatch independently re-reads the same diff (no shared digest), carries `review-rigor.md` (2,911 B) verbatim **plus** ~750 B of body restatement of the same contract **plus** a mermaid diagram encoding it a third time. Defect floors overlap: N+1/LAZY checked 3×, Kafka 3–4×.
- The fix→re-spawn loop has **no iteration cap** (only the ~8-consecutive-Stop backstop in a different hook). ~60–100K tokens per review round, re-paid from scratch each round.
- Even trivial tier pays one 10–13K opus reviewer dispatch, because `set-review pass` in `bin/claudehut-state` (L245-287) unconditionally requires a review.md passing 4 content greps.

### RC3 — Always-on injection tax (≈10–15%, worst on long sessions)
- **SessionStart:** `scripts/bootstrap.sh:56` cats the ENTIRE 10,191 B workflow SKILL.md + top-12 learnings (per-entry length uncapped) + Summer KB block ≈ **13.2 KB (~3,300 tok) per event** — and the matcher (`hooks/hooks.json:5`) includes `resume|clear|compact`, so every compaction re-pays it. Self-amplifying: the injection consumes window, accelerating the next compact.
- **Every prompt:** `scripts/inject-phase.sh` emits 136 B–1.8 KB unconditionally — phase line even when unchanged, a 449 B triage block duplicating SKILL.md Phase 0 already in context, up to 5 learnings.
- **Triple-paid learnings:** same records injected at session start (top-12), per prompt (top-5, no exclusion of IDs already written to `state/<sid>.injected.json`), and per auditor (top-8). The random nonce (`scripts/inject-learnings.sh:29`) makes identical blocks never byte-identical, defeating any dedupe. ~3–5K duplicated tokens per focused task.

### RC4 — A haiku agent spawns on EVERY Stop (≈5–10% + the worst latency offender)
- `hooks/hooks.json:61`: agent-type hook, claude-haiku-4-5, 45s timeout, fires at the end of **every assistant turn**, not just completions. The "cheap early-exit" still costs a full agent spawn + ≥2 model round-trips (~2.5–8K haiku tok) + 3–45s latency; a blocked-stop retry loop re-fires it up to ~8×. Both of its checks (review==pass; evidence has pass counts + file:line loci) are mechanically greppable inside `scripts/gate-done.sh` for zero model cost. ~150–240K haiku tokens over a 30-turn session.

### RC5 — Skill & rule payload duplication (≈10–15%)
- The write-gate skill rail (`scripts/gate-write.sh:92-95`) forces the full 16,213 B `skills/implement/SKILL.md` into main context for **every task in every tier** (one-line comment fix included), then it's preloaded **again** into every implementer dispatch. ~60% is orchestration irrelevant to trivial/small.
- 12 rule templates glob `paths: "**/*.java"` (36,322 B ≈ 9.1K tok) and auto-load in **every context touching any Java file** — main thread + each implementer worktree + each auditor. A full task = up to 9 contexts ≈ 80K tokens; cqrs/ddd/hexagonal (9,385 B) load even where unused. Playbooks (`skills/implement/references/`, ~100KB) duplicate the same topics: one JPA entity loads playbook jpa.md 8,108 B AND rules jpa + lombok-jpa-safety + n-plus-one = 22.5 KB on one topic.

### RC6 — Artifact double-pay and output ceremony (≈8–12% of full tier)
- brainstorm content paid 3× (agent output → main re-writes brainstorm.md → planner reads); spec.md 4–6×; plan.md 4–5× including verbatim T-row paste into each implementer and the TaskCreate mirror (`skills/write-plan/SKILL.md` L36-62, `skills/brainstorm/SKILL.md` L45-49).
- Reviewer ✓ rows demand file:line + quoted excerpt per item (`skills/review/references/review-rigor.md` rules 3-4), then the main thread re-opens every cited locus (`skills/review/SKILL.md` L101-107) — 15–60K tok/round of opus output + re-reads consumed only by a format gate.

### RC7 — Agent corpus bloat paid per dispatch (≈5%)
- Mermaid flowcharts in all 14 agent bodies: 15,142 B, **19.7% of the corpus**, each restating adjacent prose (~210–350 tok/dispatch). Identical 931 B Summer KB grounding block pasted into 9 agents (8,379 B), unconditional even on non-Summer projects, while bootstrap injects it again. 1,955 B of duplicated MCP-degradation prose in 3 reviewers. 12,294 B more mermaid across the 10 SKILL.md files plus design-history prose ("split out of Brainstorm, v0.4") that persuades the maintainer, not the model.

### RC8 — Fragile/dead hooks that waste generated output (small % but nasty failure mode)
- `UserPromptExpansion` and `PostToolUseFailure` (`hooks/hooks.json:18,49`) are not documented Claude Code hook events; all errors are swallowed with `|| true`. If the expansion event never fires, slash-command users never open the skill rail and hit a deny loop — and the gate-by-denial design means each denial discards a **fully generated Write payload** (~1.5K output tokens, the expensive kind), with the reason then sent **twice** (`scripts/gate-write.sh:15` duplicates it in two fields, ~900 B per deny). The script's own comments record a 69% pre-fix bypass rate — denials are the common path.

## 3. v0.10 structural changes

### 3.1 Tier routing inversion + real micro-lane (the #1 pain fix)
**Design:** `bootstrap.sh` arms `complexity: null` instead of `"full"`. The write gate already computes changed-file counts deterministically (`fastlane_bound_ok` in `scripts/gate-write.sh`) — use it for **routing, not just denial**: ≤2 non-sensitive files auto-applies the small bound; explicit `set-complexity full` required only when the bound is exceeded. Add a tier-aware completion rail: `set-review pass --inline --test-cmd '...' --passed N` records evidence directly in state for trivial (and green small) — gate-done can re-run/verify the command — skipping the reviewer dispatch and review.md entirely. Extend inline discover (trivial's 3-grep scan) to small tier, or collapse explorer+scanner into one dispatch (explorer's output is consumed only by the scanner anyway, `skills/discover/SKILL.md` L66-91). Add a `/debug` fast lane (reproduce→fix→verify) that legally bypasses spec→plan gates in `bin/claudehut-state`.
**Saving:** trivial 25–40K → 8–12K; small 55–85K → 25–35K; kills the 6–8× missed-triage multiplier. **Effort:** ~3–4 days (state machine + gate + 2 skills).

### 3.2 Review redesign: consolidate, diff-scope, score with haiku
**Design (adopts the official code-review pipeline shape, §5):** small/medium diffs → ONE sonnet reviewer whose prompt appends only the matched specialists' defect-floor tables (~1–2 KB each, far cheaper than whole agent contexts) and receives the diff pasted in. Full tier → 2–4 narrow-lens sonnet reviewers dispatched **in one message as parallel background subagents**, plus per-finding haiku confidence scoring with an 80 cutoff instead of extra reviewers. Deterministic auditor selection by diff paths in a script (db-reviewer only when entities/migrations change). Output contract per auditor: one JSON `{verdict, blocking:[{file,line,issue}], advisory_count}` ≤30 lines, full detail to a file under `.claude/claudehut/review/` referenced by path; `verify-subagent.sh` enforces length. Differential re-review on loop rounds.
**Saving:** 40–70% of the largest phase ≈ 25–50K/task full tier, ~10K trivial/small — on top of the sonnet re-pricing. **Effort:** ~4–5 days.

### 3.3 Implement-skill split + subagent isolation
**Design:** split `skills/implement/SKILL.md` (16,213 B) into implement-core (~2–4 KB: Iron Law, cycle, create-time table, red flags — satisfies the gate rail under the same skill name) + `references/orchestration.md` (worktree/parallel/task-mirror machinery, read only when a plan.md exists). Give `claudehut-implementer` `skills: [claudehut:implement]` preload so the 100 KB playbook pool lives **only** in the implementer's disposable context; mark heavy non-interactive skills (`discover` reuse scan, `capture-learnings`) `context: fork` so their grep/read churn never touches the main window. De-duplicate playbooks vs rules: the create-time table points at the same rule files that auto-load on edit; playbooks keep only genuinely create-time content (decision ladders).
**Saving:** ~8–10K/full task, ~3K/trivial; 10–18K per implementer dispatch. **Effort:** ~3 days.

### 3.4 Rules diet
**Design:** narrow the 12 `**/*.java` globs (cqrs/ddd/hexagonal → opt-in stack tag or package globs); merge the 7 `coding/*` files into one ≤4 KB terse DO/DON'T rule with examples moved to a lazily-read reference; extend stack tags to all 55 templates (detect wiremock/virtual-threads/architecture from build files in `bin/claudehut-init:119-141`; typical service emits ~25 not ~45 rules); CI check failing any template without `paths:`.
**Saving:** ~50–70K per full task (the 9.1K-tok always-Java load × up to 9 contexts), ~12K per trivial task. **Effort:** ~2–3 days.

### 3.5 Artifact digest pipeline
**Design:** pass digests, not files: planner gets spec's Decision+AC sections only; plan-reviewer gets T-table + AC list; each implementer gets only its own T-rows + referenced ACs (never §3 diagrams or others' sketches); brainstormer writes brainstorm.md itself (give it Write) instead of returning content for main to re-emit; brainstorm gets a word budget like reuse-scan's ≤450 words (losers one line each); skip the TaskCreate mirror below N tasks; plan-review APPROVE = verdict + one line per check; scoped plan re-review on post-APPROVE edits (pass previous plan-review.md + a plan diff) instead of the byte-hash full re-dispatch (`bin/claudehut-state:206-212`).
**Saving:** ~15–25K per full-tier task + ~8–11K per plan-revision cycle. **Effort:** ~2–3 days.

### 3.6 Hook diet + phase-boundary /clear
**Design:** add `"if": "Write(*.java)"` / `"Edit(*.java)"` to format-java.sh and lint-reuse.sh so markdown/spec writes don't spawn processes; `once: true` for one-time injections (Summer KB pointer); after spec-approved and review-passed gates, the skill (or a Stop-hook `systemMessage`) recommends `/clear` — the next phase rehydrates from `.claude/claudehut/state` + spec/plan files (PreCompact persist already exists), replacing compaction-heavy long sessions with cheap fresh ones.
**Saving:** hook spawn latency on every non-Java write; avoids compaction requests and the re-paid SessionStart block. **Effort:** ~1–2 days.

### 3.7 (Candidate, behind a flag) Native agent memory replaces the learnings plane
**Design:** `memory: project` on claudehut-learner (writer) and reviewer/planner (readers) — the harness injects each agent's first 200 lines/25 KB of MEMORY.md, auto-manages Read/Write, and is git-shareable. Retires the flock lock (the commit-963cee8 MEM-1 bug class moves to Anthropic's court), the injection scripts, and the triple-injection sites; `/learn` becomes a curation pass. Keep the jsonl store one release as fallback.
**Saving:** deletes ~3 scripts + all learnings-injection tax; bounded 25 KB/agent. **Effort:** ~3–4 days incl. migration; ship as opt-in in v0.10, default in v0.11.

## 4. New Claude Code / Anthropic features to adopt — VERIFIED only

All verified against sources by the researchers; each mapped to a concrete claudehut change.

1. **Per-agent/per-skill `effort` + `maxTurns` + `model` frontmatter** — the primary token lever on 4.7+/5 models; hooks receive `$CLAUDE_EFFORT` (CC v2.1.78/80/120/133). → §2#2 re-tiering; `maxTurns` caps on read-only auditors; inject-phase reads `$CLAUDE_EFFORT` to skip verbose tier text at low effort. *Source: https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md, https://code.claude.com/docs/en/skills*

Note Sonnet 5's tokenizer yields ~30% more tokens for the same text — factor into byte→token estimates. → reviewers to sonnet during promo; document tiering in plugin README. *Source: CHANGELOG.md v2.1.197/v2.1.219 + bundled claude-api skill*
3. **`context: fork` + `agent:` binding + `background` on skills** (background-by-default since v2.1.218) → fork discover's reuse scan and capture-learnings; keep write-spec/write-plan inline (they own AskUserQuestion gates, which forks can't do). *Source: https://code.claude.com/docs/en/skills, CHANGELOG.md v2.1.0/v2.1.218*
4. **Subagent `skills:` preload** (full content into the subagent's context at startup) → implementer preloads implement-core; 100 KB playbooks never touch the main session. *Source: https://code.claude.com/docs/en/sub-agents*
5. **`memory: user|project|local` agent frontmatter** (persistent dir, 200-line/25 KB MEMORY.md injection, git-shareable) → §3.7. *Source: https://code.claude.com/docs/en/sub-agents, CHANGELOG.md v2.1.33*
6. **Hook `if` conditions (permission-rule syntax), `once`, async, and prompt/agent hook types** — prompt hooks are one fast-model call vs agent hooks' full tool-using loop; docs' cadence table says prefer Stop over PostToolUse. → §3.6 hook diet; the Stop verifier becomes greps in gate-done (agent hook deleted). *Source: https://code.claude.com/docs/en/hooks, CHANGELOG.md v2.1.85/v2.1.118*

9. **Skill `disable-model-invocation: true` and `paths:` frontmatter** — descriptions vanish from standing context for orchestrator-invoked skills; paths-scoped skills load only on matching files. → mark all 10 state-machine-driven phase skills `disable-model-invocation: true`; paths-scope Java rule skills. *Source: https://code.claude.com/docs/en/skills*
10. **Background-by-default subagents, 20-concurrency, depth-3 nesting** (v2.1.198/217/219) → review fan-out dispatched in one message as parallel background agents; set `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` conservatively as a rate-limit guard. *Source: https://code.claude.com/docs/en/sub-agents, CHANGELOG.md*
11. **Prompt-cache mechanics:** UserPromptSubmit/hook injections APPEND to the conversation layer and do **not** break cache — the cache is broken by model/effort switches, fast-mode toggles, non-deferred MCP changes, compaction, CC upgrades; subscriptions get 1h TTL on the main conversation, subagents only 5 min; `ENABLE_PROMPT_CACHING_1H` for API keys. → never have a phase skill run `/model`//`effort` in the main session (per-subagent frontmatter is fine); keep bootstrap output deterministic (sorted, no timestamps), volatile bits last. *Source: https://code.claude.com/docs/en/prompt-caching*
12. **Rebuilt `/code-review`** (-25% tokens, background fork, never auto-runs since v2.1.215) + `disableBundledSkills` → either delegate generic correctness to bundled `/code-review medium` and keep only domain auditors, or document `disableBundledSkills` to drop overlapping bundled descriptions. *Source: CHANGELOG.md v2.1.196/v2.1.218/v2.1.215*
13. **Batch API at 50% off** → run evals/ and periodic learnings distillation as haiku batch jobs from CI — zero draw on interactive premium-plan limits. Use `claude -p --bare` for scripted calls (skips hooks/plugin sync) and pin `effort: low` + explicit thinking-off — 5-family models think by default when `thinking` is omitted. *Source: bundled claude-api skill (batches.md, SKILL.md)*

## 5. Ideas from top plugins worth stealing

1. **Official code-review plugin's pipeline** — narrow-lens parallel Sonnet reviewers over the **diff only**, then a dedicated Haiku agent per finding assigns 0–100 confidence, threshold 80, Haiku re-verifies before posting. Blueprint for §3.2. *https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/plugins/code-review/commands/code-review.md*
2. **superpowers issue #190** — the community treats preloading skill bodies as a bug: ~22K tokens preloaded vs ~1.4K expected under the Discovery→Activation→Execution model. Directly indicts `bootstrap.sh:56`; adopt its budget discipline: SessionStart block ≤1.5K tok, description ≤100 tok, everything else behind a Read — and add a lint budget (~2 KB) for any file a hook cats into additionalContext (`scripts/lint-prompt-length.sh` already exists but exempts the biggest injected file). *https://github.com/obra/superpowers/issues/190*
3. **EveryInc compound-engineering** — learnings live in repo docs read **only at plan-time** (brainstorm/plan grounding), nothing injected at session start; explicit `/ce-debug` fast lane skips brainstorm/plan for bug fixes. Model for §3.1's `/debug` lane and the learnings consumption move. *https://github.com/EveryInc/compound-engineering-plugin*
4. **wshobson/agents** — explicit 5-tier model strategy across 203 agents: Haiku for operational tasks, Sonnet default, Opus only for architecture/security. Validates §2#2. *https://github.com/wshobson/agents*
5. **Anthropic context-engineering blog** — subagents return condensed 1,000–2,000-token summaries; just-in-time retrieval via lightweight identifiers. Basis for the auditor JSON output contract (§3.2). *https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents*
6. **claude-mem** — inject a ≤300-token index (titles + one-liners), retrieve full entries on demand; an `rg`-over-markdown retrieval suffices for a per-repo learnings dir. [unverified savings claims — the pattern, not the numbers] *https://docs.claude-mem.ai/introduction*
7. **caveman/cavecrew** — haiku-investigate / sonnet-build / haiku-review triad as a fast lane, telegraphic agent prompts (claudehut's 76.7 KB agent corpus is standing input on every dispatch). [unverified — maintainer-claimed ~60% inter-agent traffic cut; adopt the prompt-compression idea, not the benchmark] *https://github.com/JuliusBrussee/caveman*

## 6. Do-NOT-do

1. **Don't adopt dynamic workflows ("ultracode") or agent teams** — explicitly token-intensive (teams ~7× standard sessions); directly conflicts with the cost goal. Only ship the `workflowSizeGuideline: small` guard. *CHANGELOG.md v2.1.154/v2.1.178*
2. **Don't wire fast mode into any phase** — $10/$50, billed from usage credits only, and the first mid-session toggle re-bills the entire conversation uncached. Latency purchase, not a cost tool. *https://code.claude.com/docs/en/fast-mode*
3. **Don't have skills switch model/effort in the MAIN session** — session-level switches invalidate the whole prompt cache (can re-bill 100K+ tokens deep in a session). Per-subagent/per-skill frontmatter is the safe channel. *https://code.claude.com/docs/en/prompt-caching*
4. **Don't "fix" inject-phase.sh on cache grounds** — hook injections append; they don't break cache. The real cost is cumulative transcript growth — fix with delta emission (§2#4), not by touching the prefix.
5. **Don't fork write-spec/write-plan into background subagents** — they own AskUserQuestion approval gates, which background forks can't service.
6. **Don't preload broad skills into reviewers via `skills:`** — that frontmatter injects FULL content at startup, the opposite of lazy loading. Preload only the implementer's single core skill.
7. **Don't delete the deterministic gates themselves** (reuse-scan artifact, test-first rail, evidence-gated completion) — every audit found the waste in *ceremony around* the gates, not the gates. The state machine is the asset that makes cheap models safe.
8. **Don't build vector-DB learnings retrieval** — a per-repo markdown dir with `rg` and a ≤300-token index is sufficient; and native `memory:` (§3.7) may obsolete it anyway.
9. **Don't over-fan-out reviews for wall-clock** — each subagent is a cold cache (5-min TTL) that re-reads files; below full tier, one consolidated reviewer with pasted diff beats parallelism on both tokens and dollars. *https://code.claude.com/docs/en/prompt-caching#subagents-and-the-cache*

## 7. Estimated combined impact

Baseline from the cost model (tokens ≈ bytes/4; ~2.5K harness overhead/dispatch; Opus $5/$25, Sonnet promo $2/$10, Haiku $1/$5).

**Simple (trivial tier, "add a validation annotation")** — before: **25–40K tok** (~3K task-relevant), incl. one opus reviewer dispatch 10–13K, implement skill 4.05K, Stop haiku ~2.5–5K, injections ~3–6K.
After: inline evidence rail removes the reviewer dispatch (−10–13K); implement-core replaces the full skill (−2.5K); Stop haiku deleted (−2.5–5K); injection diet (−3–5K); rules glob fix removes the 9K always-Java load from the surviving contexts.
→ **≈ 8–12K tok, ~70% cut** — and what remains is haiku/sonnet-priced, so **dollar cost drops ~85–90%** (≈ $0.10–0.15 → ≈ $0.02).

**Standard (small tier)** — before: **55–85K tok** (mandatory explorer+scanner pair 25–38K, reviewer dispatch, injections).
After: inline/one-dispatch discover (−22–35K); single consolidated sonnet reviewer (−~8–12K and re-priced); injection + skill diet (−5–8K).
→ **≈ 20–35K tok, ~60% cut**; sonnet/haiku pricing throughout.

**Complex (full tier)** — before: **190–280K input + 15–25K output**, ~120–190K of it opus-priced ≈ **$2.5–4/task**.
After, additively: review consolidation + diff digest + loop caps (−25–50K); artifact digests (−15–25K); implement split ×N implementers (−10–20K); agent-corpus diet ~6 KB/dispatch × ~12 dispatches (−15–18K); bootstrap/prompt diet (−8–12K); rules scoping (−30–50K across contexts) → **≈ 80–120K tok**. Model re-tiering then re-prices most of that from opus to sonnet-promo (2.5× cheaper) with haiku on test-runner/scoring:
`(100K in × $2 + 12K out × $10)/1M ≈ $0.32` sonnet-share + residual opus (brainstorm/plan ~25K in, 4K out ≈ $0.23) + haiku noise → **≈ $0.6–0.9/task, a 3.5–5× dollar cut** at roughly 2.5× fewer tokens.

**Team rate-limit effect (the #1 pain):** premium-seat windows drain at token-cost rates, so the combined effect on the shared 5-hour/weekly pools is multiplicative — ~2.5–3× fewer tokens × ~2–2.5× cheaper average model ≈ **5–8× more claudehut tasks per seat window**, with the biggest relative relief exactly where the pain is: simple tasks stop paying a $0.10-plus, 30-turn, 45s-per-stop framework tax for a one-line change.
